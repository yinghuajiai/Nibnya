# 🇨🇳 中文

## ⚠️ 变更（必读）

1. **应用已改名**：中文「樱喵NBT」/ 英文「Nibnya」（原名 NBT 编辑器）。
2. **包名已改**：`yhjmew.minecraft.nbteditor` → `yhjmew.nibnya`。
   系统会把它当成**另一个应用**，**无法覆盖安装，必须先卸载旧版**。
   卸载会清掉：**草稿箱**、**全部设置**（路径 / 主题 / 语言 / 线程数…）；若你**没有**授予「所有文件访问」权限，
   旧版私有目录里的**备份**与**回收站**也会一起丢失。放在公共目录 `Download/` 下的数据不受影响。
3. **数据目录已改名**：`Download/NbtEditor_Data/` → `Download/Nibnya/`。
   首次启动会检测到旧目录并询问是否迁移，**不会自动删任何东西**；全部搬完之前旧目录一直保留。
   也可随时在「设置 → 📦 迁移旧数据」手动执行。
4. 测试版与正式版**共用同一个签名密钥**。

## ✨ 新增

- **回收站**：删除存档不再直接抹掉，而是先移入回收站，可恢复 / 彻底删除 / 全部恢复 / 清空，
  支持自动清理（默认 30 天，可配 7 / 30 / 90 / 自定义）。
- **导出 `.mcworld`**：把整个世界打包成可被 Minecraft 直接导入的存档包，默认存 `Download/Nibnya/Worlds/`。
- **草稿箱**（取代原来的自动弹窗）：编辑中的未保存内容会定时落到草稿箱，由你主动找回，不再打扰；
  间隔 / 上限 / 是否保留改动前数据均可配。
- **剪贴板重做**：复制会同时写入系统剪贴板，支持 JSON / SNBT / 纯文本三种格式；粘贴自动识别格式。
- **导出到文件**：可导出到下载目录，也可走 SAF 自选目录（无需任何权限）。
- **SAF（存储访问框架）完整实现**：详见下方「修复」第 1 条。
- **列表体系**：选择世界 / 草稿箱 / 备份三个列表统一显示格式（世界名 + ID / 类型标签 / 时间 / 相对时间），
  底部动态标签栏，长按管理菜单。
- **多线程配置真正生效**：文件操作与拼图生成都可开关多线程并指定并发数。
- 新增 **xxxhdpi（192×192）** 应用图标。

## 🐛 修复

1. **SAF 模式下的保存会「假装成功」**（最严重）：SAF 路径下写回完全没有实现，
   且有两处**无条件报告成功**（不检查命令退出码），实际数据根本没写进去，界面却提示「已保存」。
   现在读写删全部走 DocumentFile，写回采用「先写临时目录 → 改名让位 → 改名为正 → 失败回滚 → 成功后才删旧数据」
   的顺序，**任何失败都会明确报错，绝不再谎报成功**。
   同时修好了 SAF 模式下**打开存档没有反应**（两个 SAF 读取函数此前是死代码，从未被调用）。
2. **备份目录有两套不一致的定义**，导致「清空本存档备份」清的是空目录却提示已清空、
   删除存档时统计备份数恒为 0（于是从不询问「是否连带删备份」，备份被残留）。现在目录定义只有一处。
3. **树形视图**：新增 / 删除后不重建节点导致看不见、List 元素删除改错对象、根级字段「操作失败」、
   无法保存（原来会提示「请先切换回默认视图」）。
4. **玩家数据新增 List 后保存丢失**：真根因是**误删了 LevelDB 的索引文件**（`CURRENT` / `MANIFEST-*`），
   新数据写进 `.ldb` 却无法被索引定位。现在只清理打开时会自动重建的 `LOCK` / `LOG`。
5. **大存档被误判为 LOCK 导致打不开**。
6. **地图画生成内存溢出**：改为降采样解码 + 并发限流 + 及时回收。
7. **一展开设置就弹出「自定义」输入框**、设置面板无法滚动、选项文字被截断。
8. **设置自定义间隔 / 线程数时崩溃**（`ArrayAdapter.remove` 不支持不可变列表）。
9. **会话恢复对话框张冠李戴**（编辑世界数据却显示玩家），以及「丢弃后会话又复活」。
10. **标签栏不贴底**（`AlertDialog` 会把自定义视图塞进 `wrap_content` 容器，只改窗口尺寸无效）。
11. **issue #6 权限问题**：自定义路径保存时不再误报「需要 Shizuku」。
12. **release 变体编译失败**（`var x` 与手写 `setX()` 撞 JVM 签名）。

## 🔧 改进

- 按功能域重新分包（`nbt/` `db/` `editor/` `world/` `mapart/` `util/`），为后续加功能留出结构。
- 补齐国际化：中英字符串严格对称，清掉代码与布局里的硬编码文案。
- 崩溃日志同时写入公共目录与私有目录。
- 复制的缓冲区 1KB → 64KB + 零拷贝，拷贝速度明显提升。
- 数据目录路径集中到 `AppDirs` 一处定义（以前散落在 8 个文件里）。

## 🐞 已知问题

- 超大存档 / 大量 NBT 时内存吃紧，可能被系统杀掉（待优化）。
- 地图平面展示与编辑（区块查看 / 修改 / 移动）尚未实现。
- 自动更新、存档多开、Blocktopograph 风格主题尚未实现。
- 回收站「全部恢复」的大批量稳定性、自动清理的实际行为仍待长期观察。

# 🇬🇧 English

## ⚠️ Changes (please read)

1. **The app has been renamed**: "Nibnya" in English / "樱喵NBT" in Chinese (formerly NBT Editor).
2. **The package name has changed**: `yhjmew.minecraft.nbteditor` → `yhjmew.nibnya`.
   Android treats it as **a different app**, so it **cannot be installed over the old version — you must uninstall first**.
   Uninstalling removes: the **draft box** and **all settings** (path / theme / language / thread counts…).
   If you did **not** grant "All files access", the **backups** and **recycle bin** inside the old app's private
   directory are lost as well. Data under the public `Download/` folder is not affected.
3. **The data folder has been renamed**: `Download/NbtEditor_Data/` → `Download/Nibnya/`.
   On first launch the app detects the old folder and asks whether to migrate. **Nothing is deleted automatically**;
   the old folder is kept until everything has been copied.
   You can also run it any time from "Settings → 📦 Migrate old data".
4. The test build and the stable build now **share the same signing key**.

## ✨ Added

- **Recycle bin**: deleting a world no longer erases it — it is moved to the recycle bin first, where you can
  restore / delete forever / restore all / empty it, with automatic cleanup (default 30 days; 7 / 30 / 90 / custom).
- **Export `.mcworld`**: packs a whole world into a file Minecraft can import directly;
  saved to `Download/Nibnya/Worlds/` by default.
- **Draft box** (replaces the old pop-up): unsaved edits are periodically written to the draft box and you
  retrieve them when you want — no more interruptions. Interval / limit / keep-original are all configurable.
- **Clipboard rework**: copying also writes to the system clipboard, in JSON / SNBT / plain text;
  pasting detects the format automatically.
- **Export to file**: to the Download folder, or to a folder you pick via SAF (needs no permission at all).
- **Full SAF (Storage Access Framework) support**: see fix #1 below.
- **List system**: the world picker / draft box / backup lists now share one display format
  (world name + ID / type tag / time / relative time), a dynamic bottom tab bar, and long-press menus.
- **Multi-threading actually takes effect**: file copy and map-art generation can be toggled and tuned.
- Added an **xxxhdpi (192×192)** app icon.

## 🐛 Fixed

1. **Saving in SAF mode silently "pretended to succeed"** (most serious): write-back was not implemented for SAF
   paths at all, and two places **reported success unconditionally** (the command exit code was never checked) —
   the data was never written, yet the UI said "Saved".
   Reads, writes and deletes now all go through DocumentFile, and write-back uses
   "write to a temp dir → rename the old one aside → rename the new one into place → roll back on failure →
   delete the old data only after success". **Any failure is now reported honestly.**
   Also fixed **opening a world doing nothing** in SAF mode (the two SAF load functions were dead code that was never called).
2. **Two inconsistent definitions of the backup directory** caused "clear this world's backups" to clear an empty
   directory while reporting success, and made the backup count always 0 when deleting a world (so the app never
   asked whether to delete the backups too, leaving them behind). There is now a single definition.
3. **Tree view**: new/deleted nodes were invisible (no rebuild), deleting a List element modified the wrong object,
   root-level fields failed with "operation failed", and saving was blocked (it used to say "switch back to the
   default view first").
4. **Player data lost after adding a List**: the real root cause was **deleting LevelDB index files**
   (`CURRENT` / `MANIFEST-*`), so new data written into `.ldb` could not be located by the index.
   Only `LOCK` / `LOG` (recreated automatically on open) are cleaned now.
5. **Large worlds misdetected as LOCK and refusing to open.**
6. **Out-of-memory while generating map art**: now uses downsampled decoding + concurrency limits + timely recycling.
7. **Opening Settings immediately popped up the "custom" input box**, the settings panel could not scroll,
   and option labels were truncated.
8. **Crash when entering a custom interval / thread count** (`ArrayAdapter.remove` on an immutable list).
9. **The session-restore dialog showed the wrong target** (world data labelled as player data), and a discarded
   session came back to life.
10. **The tab bar would not stick to the bottom** (`AlertDialog` puts a custom view inside a `wrap_content`
    container, so resizing the window alone has no effect).
11. **issue #6 permission problem**: saving to a custom path no longer falsely claims "Shizuku is required".
12. **Release build failure** (`var x` clashing with a hand-written `setX()` on the JVM signature).

## 🔧 Improved

- Reorganized packages by domain (`nbt/` `db/` `editor/` `world/` `mapart/` `util/`) to leave room for growth.
- Completed internationalization: EN/ZH string keys now match exactly, hardcoded text removed from code and layouts.
- Crash logs are written to both the public and the private directory.
- Copy buffer 1KB → 64KB plus zero-copy; copying is noticeably faster.
- All data-folder paths are now defined in one place (`AppDirs`) instead of being scattered across 8 files.

## 🐞 Known issues

- Very large worlds / lots of NBT can exhaust memory and get the app killed (still to be optimized).
- Map plane view and editing (chunk view / modify / move) is not implemented yet.
- Auto-update, multiple worlds open at once, and Blocktopograph-style themes are not implemented yet.
- The stability of "restore all" with large numbers of recycle-bin entries, and the actual behavior of
  automatic cleanup, still need long-term observation.
